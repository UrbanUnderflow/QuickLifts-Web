# Donation monthly giving release

User approval on 2026-11-02 permits new donation-specific recurring billing records. Existing PIL account settings, keys, webhook registrations, Pulse products/prices/plans and customer subscriptions remain unchanged. The only new live records are created at a donor's authorized checkout; deployment does not create a live charge or test subscription.

Donation checkout uses Stripe subscription Checkout with inline USD monthly price data, quantity one and the exact chosen cents. Product, session and subscription metadata identify AthleticMind giving separately from Pulse memberships. No trial, transfer destination, application fee, trainer routing or membership metadata is supplied. Required monthly authorization and current payment terms are validated before creating Checkout. The compact payment terms UI remains. Optional public sharing stays off by default; only its redundant explanatory sentence was removed.

Protected durable session/request bindings are persisted before exposing the Checkout URL. Retries retrieve the existing session; changed inputs or finished/expired sessions cannot silently create a second plan. Existing general webhook donation dispatch isolates checkout, subscription and invoice events from membership provisioning. The existing coach webhook ignores donation metadata.

Public snapshots reconcile only server-tracked intents and sessions. Each monthly batch reads one tracked session and at most 20 invoices for its specific subscription, with four concurrent payment reads. Continuation cursors, distributed lease, cache and cooldown remain in the existing Firestore infrastructure. A complete snapshot includes verified paid charges less refunds, excludes unpaid or disputed amounts, and aggregates each plan into one school vote. No future scheduled payments count as collected. Failures and incomplete cycles retain explicitly stale prior totals or fail closed; no unbounded account-wide scan or new scheduled service is introduced.

Validation includes unit tests, real local Firestore pagination/privacy tests, existing Pulse payment regressions and Stripe test-mode Checkout plus test-clock initial payment, renewal, refunds, decline and application cancellation. Test-clock lifecycle uses an explicit synthetic session binding to the actual test subscription; this is not proof of a completed hosted checkout or live settlement. A legacy coach referralCode assertion also fails unchanged on the pre-release baseline and is outside this release.

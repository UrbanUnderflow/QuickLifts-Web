## Local release findings

1. **High: a group is sent inside a synchronous HTTP request.** `src/lib/coach-communications/service.ts:109` loops through up to 25 recipients with repeated authorization/database reads and provider calls. There is no durable delivery worker or provider timeout in the shared sender. A process deadline can leave a partial batch and a message stuck at `sending`. Before rollout, implement durable per-recipient jobs, bounded provider calls and explicit operator reconciliation for unknown outcomes. Prove recovery with simulated termination and partial failure.
2. **High: request recovery does not survive navigation/reload.** `CoachSmsInbox.tsx:13` keeps the request ID only in React state; line 45 creates a new UUID when that state is lost. Server dedupe protects retries of the same ID, but a coach retrying after a reload can create another group. Add a server-backed batch list/resume flow with status lookup. Keep recipient/message content out of persistent browser storage where possible. Test lost responses, reloads and team switches.
3. **Medium: a permanent validation failure traps the current compose screen.** The UI stores `pending` before the request and keeps it for all errors, including a 400/403/409 rejection. Edit and recipient selection remain disabled. Distinguish known-not-started validation failures from uncertain sends, and let the coach correct only the former. Do not clear uncertain IDs merely to enable editing.
4. **Release blocker: contact onboarding is deliberately absent.** Only separately reviewed server-owned contact/consent records are eligible. The survey consent cannot populate those records. Build an auditable contact consent/provisioning workflow after cohort identity and the permitted outreach basis are settled; do not use manual fabricated flags to make the UI send.
5. **Operational gap: provider acceptance is the final outbound status.** No delivery-status callback or unknown-status resolution UI exists. The UI labels acceptance honestly, but launch support requires a way to distinguish delivered, failed and uncertain messages. Configure signed callbacks and a reconciliation path before broad use.
6. **Product gaps:** replies require manual refresh; the existing navigation unread count is for in-app conversations, not SMS. Contacts without provisioned names render as `Athlete`. Add accurate SMS unread/history behavior and clear identity labels as the consent workflow is completed. One shared sender/phone binding supports one team conversation; multi-team numbers need an explicit routing design.
7. **Verification gaps:** no full Next production build, authenticated full-dashboard/API integration test, live provider test, native phone-link test or account-deletion/retention integration was completed. The fake database tests do not cover real Firestore paging with equal timestamps, batch rate limits or all transactional races. Broaden those targeted checks before release, without touching production data.
